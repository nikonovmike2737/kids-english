# Kids English — Остров английских приключений
**Статус: CONCEPT / FOR OWNER APPROVAL. Не принято и не включено в Production.**
Дата: 2026-11-23. Концепция продуктовой механики и визуализации. Иллюстративный макет показан владельцу в чате; не является кодом.

## Цель и идея
Отойти от классического списка карточек в сторону путешествия по интерактивной карте. Котёнок из текущего брендинга ведёт ученика по сказочному острову, где микрозадания обозначены остановками на тропинке. На пройденных этапах появляются собранные ключи, затем можно открыть сундуки и получить золотые монеты. Карта — новый способ входа в **те же задания**, без изменения методологического правила «верный ответ без подсказки, три жизни на урок».

## Предлагаемая структура MVP
- **Локация 1 — Feelings:** четыре остановки ENG-001-Q01…Q04; сундук эмоций после всех четырёх разных остановок.
- **Локация 2 — Move & Play:** ENG-002-Q01…Q04; мосты, тропинки, активные переходы; второй сундук.
- **Локация 3 — Animal Theatre:** ENG-003-Q01…Q04; театральная поляна, четыре испытания, третий сундук.
- **Финальный остров:** большой сундук после открытия всех трёх локационных сундуков; красивая анимация монет и поздравление.
- Котик — проводник, символ активного местоположения, а не подсказка к правильному варианту.
- Путь визуально обозначен пунктиром/следами лапок; пройденный этап — золотой; активный — подсвеченный; закрытый — мягко затемнённый.
- Первая версия карты без свободного движения игрового персонажа: щелчок/касание по открытой остановке; это проще, доступнее и соответствует коротким занятиям 10–15 минут.

## Экономика ключей и сундуков — предлагаемая
1. **Каждая карточка**, решённая правильно в проверке, даёт **+1 ключ**. Ошибочный ответ ключа не даёт; после исправления ошибки и правильной проверки ключ выдаётся.
2. Повторное успешное прохождение карточки в новом запуске также даёт +1 ключ (требование владельца); исключить повторное начисление за одно и то же нажатие.
3. Параллельно вести набор *уникальных завершённых остановок*; повтор одной карточки не отмечает другие.
4. Локационный сундук открывается, когда впервые успешно пройдены **все четыре разные карточки** региона. Количество ключей отображается, но само по себе не открывает сундук без уникальных завершений: нельзя обойти маршрут, фармя одно задание.
5. Награда за каждое первое открытие локационного сундука: **+10 золотых монет**. Большой финальный сундук после трёх локационных: **+50 золотых монет**, всего 80 при первом полном завершении. Монеты — игровые, без стоимости и покупок.
6. Уже открытый сундук остаётся открытым; повторные прохождения продолжают приносить ключи, но не удваивают награду за тот же сундук. Обсудить позже дополнительные способы тратить монеты (наклейки/костюмы котика).
7. Если все три жизни закончились, сбрасывается *текущая попытка* урока, а ранее заработанные ключи, монеты и пройденные уникальные остановки сохраняются. Ключи только за правильно решённые карточки.

## Хранение прогресса: не cookies, а localStorage
- Использовать **localStorage** как локальную постоянную память одного браузера на одном устройстве. Это проще, чем cookies, которые избыточно отправляются HTTP-запросами.
- Ключ хранилища: `kids-english.progress.v1`.
- Хранить только `schema_version`, `completed_task_ids`, `total_keys`, `total_coins`, `opened_chest_ids`; никакие имена/аккаунты/ответы/контактные данные, никакая сетевая аналитика.
- Прогресс живёт при закрытии вкладки и перезагрузке, пока браузер не очистит данные сайта. Между устройствами **не синхронизируется**. Приватный режим, удаление данных и блокировка localStorage могут сбросить его. При отказе хранилища работать в RAM без потери работоспособности и объяснить ограничение.
- В будущих настройках — кнопки «Сбросить путешествие» с подтверждением и, опционально, экспорт/импорт JSON для ручного переноса. Никогда не сохранять ответы тестов или персональные истории.

## Игровые экраны и управление
- Старт: карта в один экран на desktop; на мобильном — прокручиваемая последовательность из трёх локаций с явно видимым маршрутом.
- Верхняя панель: иконка котика, счётчик ключей 🔑, монет 🪙, жизни только внутри текущего урока.
- По нажатию остановки — короткое задание в том же механизме проверки с «Проверить», тремя сердцами и запретом подсказок.
- После правильного ответа — анимация золотого ключа и перемещение котика к следующей остановке. Сгорание жизни только после неправильной проверки.
- Открытие сундука — крупный контролируемый эффект, монетки, звёзды, поздравление; повторы доступных испытаний не блокировать.
- Кнопки должны работать мышью, касанием и клавиатурой, с `aria-label`; `prefers-reduced-motion` без анимаций; не показывать ответ в подсказке/карте до проверки.

## Технологическое решение (после утверждения)
- Остаётся **один** публичный GitHub repo и GitHub Pages.
- Клиентский HTML/CSS/JS (допустимо вынести в отдельные source assets в repo), без backend.
- Рекомендуемая модель данных: локальный `progress` + уроки из существующего `lessons[]` с надёжными `task_id`. Для текущих 12 вопросов назначить стабильные ID; не менять их при перестановке/редактуре без миграции сохранённых достижений.
- Проверять, что повторный правильный ответ при одной попытке не начисляет два ключа; все сундуки выдаются однократно; все игры работают после reload.
- Выпускать только после METHOD_PASS и TECH_PASS, через отдельный PR и один GitHub Actions deploy.

## Решения на утверждение владельцу
A. В MVP 12 остановок = 12 существующих заданий, три локационных сундука + один финальный?
B. Начислять **ключ за каждую успешно решённую карточку**, в том числе после повторного прохождения? (предлагается **да**).
C. Открывать сундук только после всех четырёх *уникальных* заданий в локации, не просто по сумме ключей? (предлагается **да**).
D. Хранить прогресс только в `localStorage` одного браузера без аккаунта, сервера и синхронизации? (предлагается **да**).
E. На первую версию оставить монеты как коллекцию, а обмен на вещи/костюмы отложить? (предлагается **да**).
