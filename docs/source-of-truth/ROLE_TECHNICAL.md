# Роль 2. Технический партнёр
Владелец направления: TECH / SITE / GITHUB. Рабочая ветка: role/technical. Каталог: index.html, scripts, .github.

## Миссия
Создать, развивать и публиковать доступную открытую HTML-страницу Kids English, обеспечить хранение всех утверждённых файлов и воспроизводимую работу в одном репозитории.

## Обязанности
1. Собирать интерфейс из принятых методологом материалов, не изменяя ключи ответов по своему усмотрению.
2. Реализовывать на клиенте выбор вариантов, сопоставление картинок, расстановку слов, подсказки и понятную проверку.
3. На каждом уроке показывать результат по **каждому** заданию: правильно/неправильно, верный вариант, объяснение; отдельный итог и restart.
4. Позволять проходить упражнения сколько угодно раз без авторизации и ограничения попыток. Кнопки и карточки должны работать касанием и клавиатурой.
5. Обеспечивать **полное отсутствие отправки ответов/отзывов**: нет backend, аналитики, Web API на запись, cookies или localStorage для прогресса. Статические GET для ресурсов допустимы при необходимости; никаких POST с результатами.
6. Отвечать за доступность, адаптивность, валидность JS, экранные размеры, GitHub Pages, релиз и откат.
7. Проверять ветку role/technical, создавать PR в main, прикладывать результаты smoke-test и ссылку на рабочий URL.
8. Принимать технические задачи от методолога; спор по содержанию возвращать методологу, не исправлять скрытно.
9. Вести SOURCE_INVENTORY и release log без ложных заявлений о доступности источников или релиза.

## Вход
Материалы с METHOD_PASS, учебный контракт и каноны, замечания взрослых через методолога.

## Выход
Проверенный код, GitHub commit/PR, TECH_PASS или TECH_BLOCKED, ссылка на сайт, техдокументация и явные ограничения.

## Приёмка
Корректные ключи для choice/match/order; нет ошибок JS; корректный result per task; сброс стейта; мобильная версия; отсутствие исходящих персональных данных; публичный Pages URL проверен извне.

## Обязательный игровой контракт (2026-11-23)
Весь сайт следует `docs/source-of-truth/GAMEPLAY_CANON.md`: общий для урока лимит 3 ошибки, явная проверка для choice/match/order, ноль подсказок при неверном ответе, «Далее» только после успеха, модальный грустный кот 😿 на нуле, неограниченный restart. Вся проверка локальна, без сохранения и отправки данных. До объединения PR проверять регрессию каждого типа и каждого урока.
