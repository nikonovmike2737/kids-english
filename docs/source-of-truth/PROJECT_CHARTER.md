# Kids English — канон проекта
Статус: CANONICAL. Начальная версия 2026-11-23.

## Цель
Единая система формирования игровых домашних уроков английского и публичного интерактивного тренажёра с обратной связью **только от взрослых** через чат ChatGPT/Codex.

## Продукт
Публичное название Kids English; URL github.io/kids-english. Никаких имён ребёнка, семейных данных, персональных идентификаторов в репозитории, истории коммитов и сайте.
Один публичный репозиторий; никакой второй базы, backend-сервиса или скрытого сбора данных для MVP.

## Ответственность
Методолог: программа, рабочие планы, качество английского, требования к заданиям, проверка/приёмка, выдача результата пользователю, прием обезличенных сигналов от взрослых.
Технический партнёр: фронтенд, статические файлы, UX, тестирование, GitHub Pages, техническая приёмка и сопровождение.
Оба руководствуются каноном приватности, workflow и этим документом.
Методолог утверждает педагогическую содержательную часть; технический партнёр утверждает работоспособность; итоговая публикация в main — после обоих статусов PASS.

## Ветки
main: единственный опубликованный и принятый источник истины.
canon/source-of-truth: работа над канонами; принятые версии вливаются в main PR.
role/methodologist: материалы и методологическая приёмка; принятые версии вливаются в main PR.
role/technical: реализация сайта и тесты; принятые версии вливаются в main PR.
Ветки — рабочие линии, не отдельные хранилища и не автономные постоянные источники истины. Папки docs/source-of-truth и docs/methodology сохраняются в main.

## Задачи и результаты
Запрос взрослого → методическая программа/урок с lesson_id и task_id → редакторская проверка → техническая реализация → тестирование → PR → main → GitHub Pages → пользовательский отзыв взрослого → новый рабочий цикл.
Не объявлять решение опубликованным без проверки коммита и живого сайта.

## Приоритеты
1. Достоверная и безопасная учебная программа.
2. 10–15 минут, игровая/двигательная/театральная форма; не сводить всё к экрану.
3. Самостоятельная интерактивная проверка, разбор ответов и неограниченное повторение.
4. Предсказуемость GitHub workflow без избыточной инфраструктуры.
