# Канон разработки интерактивных заданий Kids English
Статус: CANONICAL · утверждён владельцем 2026-11-23.
Владелец: методолог учебной программы. Обязателен для всех текущих и будущих карточек, уроков и типов заданий.
Связанный технический источник истины: `docs/source-of-truth/GAMEPLAY_CANON.md`.

## A. Данные карточки
Для каждого задания: `lesson_id`, `task_id` (стабильный), методическая цель, `type`, вопрос `title`, опционально `caption` и `figure`, варианты / пары / слова для перестановки, приватный ключ правильного ответа в клиентской логике, происхождение `provenance`, версия и критерии приёмки.
Форматы: `choice` (один выбор), `match` (несколько пар), `order` (фраза из слов). Другие форматы наследуют тот же контракт.

## B. Абсолютный запрет подсказок в карточке
1. До проверки вопрос, заголовок, подпись, картинка, цвет, порядок, анимация, aria-label и статус выбранных вариантов не должны прямо или косвенно **выделять правильный ответ**.
2. Если нужно выбрать картинку, её **нельзя дублировать как главную иллюстрацию над вариантами**. Антипример ENG-002-Q02: в вопросе про Swim ранее стоял пловец 🏊 и та же картинка находилась среди вариантов. Главную иллюстрацию здесь убрать.
3. Если нужно найти английский эквивалент слова, не показывать рядом изображение, однозначно указывающее нужный вариант. Антипример ENG-002-Q01 — кенгуру рядом с «прыгай»; иллюстрацию убрать.
4. Для картинки-стимула (например, «Кто это?» + 🐸 + текстовые cat/frog/...) фигура допустима, **если она сама не является готовым вариантом ответа**.
5. В `match` нельзя подсвечивать правильную/неправильную пару по мере составления: нейтральные номера только отражают выбор, а не его оценку.
6. Повторяющийся ответ в тексте вопроса, опечатки, обводка, положение элементов и лишняя объясняющая подпись считаются утечкой ответа.

## C. Три жизни — один урок
- На старте каждого прохождения урока 3 сердечка ❤️❤️❤️, **общие на весь урок**, а не по три на каждую карточку.
- Выбор до нажатия «Проверить» не тратит жизни.
- На каждой карточке пользователь составляет полный ответ и нажимает «Проверить».
- Верно: «Правильно», сердечко сохраняется, открывается кнопка «Далее» (последняя карточка — «Показать результат»). Пользователь может двигаться дальше **только** после верного ответа.
- Неверно: «Неправильно. Попробуй ещё раз», сгорает ровно **одно** сердечко, «Далее» не появляется, разрешено изменить/составить ответ и повторно проверить **ту же** карточку.
- При неверном ответе **запрещено** раскрывать ключ ответа, давать «правильный вариант», выделять его зелёным, указывать ошибочную пару или правильное место слова, показывать объяснение/подсказку, позволяющую исключить варианты.
- После потери 3-го сердечка — модальное окно поверх экрана с грустным котиком 😿 и кнопкой «Начать урок сначала». Нельзя продолжить урок с нулём жизней.
- Новый запуск обнуляет прогресс и ошибки и восстанавливает 3 жизни. Количество повторов не ограничено.
- Для `match` одна неверная проверка **всего набора пар** = одна жизнь, а не отдельная жизнь за каждый неудачный выбор пары. Не оценивать пары до общей проверки.

## D. Форма обратной связи и результаты
- При неверном ответе допускается только нейтральное подтверждение ошибки без подсказки.
- На успешной карточке короткое позитивное подтверждение, затем «Далее».
- В конце успешно пройденного урока — результат каждой карточки (решена правильно, число ошибок **до** правильного ответа), сколько жизней осталось; не раскрывать нерешённые ключи.
- Результаты существуют только в памяти открытой страницы. Не сохранять историю, не отправлять данные, не требовать регистрации.
- Классические «подсказки взрослому» разрешены в **отдельном введении в урок**, но не в тестовой карточке и не после неправильной проверки.

## E. Методическая приёмка
Проверять каждую карточку отдельно: однозначность правильного ответа, отсутствие визуальных/текстовых подсказок, отсутствие подсказок на неверной проверке, корректность двух и более попыток, общий счётчик сердец, возможность верно завершить карточку после ошибки, game over на третьей ошибке, корректность ответа и русского текста. Использовать оба сценария: успех с первой попытки и ошибочный ответ с последующей корректировкой.
